# Native loot measurements and historical save migration

New measurement files use version 3, canonical category:local keys, names and explicit icon paths. The HUD no longer resolves measurements or loot receipt icons by prototype number. Icons remain available after the acquired item leaves the inventory; changes in language refresh the visible rows.

The only old measurement reader is the one-way Metin2LootMeasurementMigration file importer. Before replacing a version 1 or 2 file, it creates a byte-identical, SHA256-named pre-native backup and flushes it to disk. It keeps the elapsed time, Yang, metin count and every item quantity. Loaded measurements remain paused. Known active aliases become canonical keys. Refinement aliases sharing a native base key are added with checked arithmetic. Unmapped or retired rewards keep independent historical snapshot rows and their recorded name/icon; no native item is invented. Duplicate identities, overflow, malformed identities or negative values reject the import and prevent overwriting the source.

The offline manifest is generated with SRC/Tools/ItemCatalogBuilder/build_loot_measurement_migration.py from a reviewed native catalogue export, the historical alias CSV and artwork catalogue. It has 13,604 historical presentation records, including 9,826 mapped to active native definitions. This manifest is used only when importing old measurement files; it is not a gameplay item lookup or an activation of deferred content.

Validation: 46 Unity measurement checks covering live gains, moves, consumption, map reload baselines, atomic saves, version 1/2 conversion, merged aliases, native and historical rows, unknown rewards, duplicates, negative values, overflow, unsupported versions and unchanged original backups. The receipt validator adds 13 checks, including explicit native icons surviving item removal. Unity Editor and non-Editor player assemblies compiled with 6000.3.27f1.

Connected local two-account proof: server-verified typed chat and whisper, linked metadata and visible tooltip; native split-stack drop/pickup receipt after commit, duplicate pickup rejection, exact measured quantity, persisted inventory and unchanged measurement after reconnect. The fixture has no old item, item_proto or item_award backend. A pre-existing skill-3 prefab exception in the reduced fixture is unrelated to these flows.
