# Phase 15E-60.5 - Legacy fallback elimination audit

Date: 2026-05-02
Scope: audit and plan only. No source-code migration performed.

## 1. Executive summary

The current ECS API is mixed:

- Pure ECS reads already exist for position and the safest stat/affect reads:
  PlayerRuntime::GetMapIndex/GetX/GetY, PointSystem::GetGold/GetMaxHP/GetMaxSP/GetLevel, AffectSystem::FindAffect/IsAffectFlag.
- Several PlayerRuntime identity and predicate accessors are ECS-first but still fall back to LegacyCharOf(e)->GetX/IsX.
- PointSystem::Get and PointSystem::GetReal are now routed through the 15E-60.8 ECS POINT router. Only explicit SRC_LEGACY_ONLY mappings may delegate, and those emit one-time diagnostics.
- Service-object and behavior APIs such as GetDesc, GetSectree, QuestSystem::GetFlag, ChatSystem sends, CombatSystem, SkillSystem, MountSystem, ItemSystem and GayaSystem still delegate heavily to CHARACTER.

Architectural conclusion:

The migration is not yet "pure ECS". It is safe and production-tested for the migrated caller side, but any ECS read API that calls LegacyCharOf in production is still an OOP bridge. The next phases should remove read fallbacks by making ECS components the single source of truth and syncing legacy writes into ECS.

## 2. Classification rules used

PURE ECS:
Reads only ECS components/tags and returns a default if the entity/component is missing.

ECS-FIRST + FALLBACK:
Reads ECS first, then calls LegacyCharOf(e)->... if the component/tag is missing.

LEGACY-FIRST:
Calls LegacyCharOf first and only uses ECS as a secondary path, or not at all.

LEGACY-ONLY:
No ECS read path exists.

WRITE/SYNC BRIDGE:
Uses LegacyCharOf to execute a legacy side effect, or to mirror legacy state into ECS. This is not a read fallback, but it is still migration debt unless the API is intentionally a side-effect adapter.

## 4. Fallback sites and cause classification

### Cause A - tag/component not trusted on all entity paths

Resolved in Phase 15E-60.6:

- PlayerRuntime::IsPC
- PlayerRuntime::IsNPC
- PlayerRuntime::IsStone
- PlayerRuntime::IsMonster

Resolved in Phase 15E-60.7:

- PlayerRuntime::GetPlayerID
- PlayerRuntime::GetEmpire
- PlayerRuntime::GetGMLevel
- PlayerRuntime::GetPacketVID
- PlayerRuntime::GetName

Remaining affected in PlayerRuntime:

- PlayerRuntime::GetDesc
- PlayerRuntime::GetSectree

Phase 15E-60.6 implementation notes:

- EntityInvariants.hpp added HasAnyTypeTag, DescribeTypeTag and ValidateCharacterTags.
- Predicate read accessors now fail closed on missing tags.
- Invariant LOG_WARN checks were added to factory creation, combat attack, and CHARACTER::Show.
- WinTest must watch for "[ECS_INVARIANT]" warnings; any warning is a root-cause hydration bug, not a reason to reintroduce fallback.

Phase 15E-60.7 implementation notes:

- ValidatePCIdentity and ValidateCommonIdentity were added to EntityInvariants.hpp.
- PlayerName is now populated for mob/NPC/stone entities in CreateMobEntity from the mob proto locale name.
- GetPlayerID/GetEmpire/GetGMLevel/GetPacketVID/GetName now fail closed with 0 or empty view when the component is missing.
- Scalar identity invariant checks were added to factory, Show, combat attack and chat send/broadcast hot paths.
- WinTest must watch for missing PlayerName/VID/PlayerID/Empire/GMLevel warnings; these indicate hydration bugs to fix at source.

Observed factory coverage:

- EntityFactory::CreatePlayer populates PlayerID, AccountID, EmpireComponent, RaceComponent, PlayerName, GMLevel, TagPC, Position, Health, Mana, LevelComponent, Experience, CharacterPoints, GoldAmount.
- EntityFactory::CreateMonster/CreateNPC/CreateStone route through CreateMobEntity<TagMonster/TagNPC/TagStone>, which populates RaceComponent, tag, Position, MapIndex, Health, Mana, LevelComponent and CharacterPoints.

Root cause:

The main factory paths are populated, but the fallback exists because previous regressions showed some runtime paths did not have reliable tags/components at read time. The likely causes are legacy creation paths, reuse of existing VID entities, or state initialization order before factory population is complete.

Required elimination action:

Add a tag/component invariant check and then remove fallback only after every CHARACTER creation path is routed through EntityFactory or calls a single post-create ECS hydration hook.

### Cause B - stale or incomplete write-side sync

Affected:

- Position components were fixed by 15E-59 Hotfix v2 and are now pure reads.
- PointSystem::GetGold/GetMaxHP/GetMaxSP/GetLevel are pure reads, but remain dependent on all legacy writes syncing GoldAmount, Health.max, Mana.max and LevelComponent.
- AffectSystem::FindAffect/IsAffectFlag are pure reads, but remain dependent on SyncAffectList after every affect mutation.

Observed position sync coverage:

- MovementSystem.cpp:152-153 syncs SetXYZ movement writes.
- MovementSystem.cpp:368-369 syncs CHARACTER::Sync.
- SessionSystem.cpp:903-904 syncs login/show placement.
- PlayerRuntimeSystem.cpp:3750-3752 syncs exit/saved-location restore.
- PlayerRuntimeSystem.cpp:3984 syncs OnMove/current position mirror.

Potential unsynced position write risks:

- LostCastleDungeon.cpp clone SetXYZ/SetMapIndex paths.
- new_offlineshop_manager.cpp NPC/entity SetMapIndex/SetXYZ paths.
- SkillSystem.cpp direct m_x/m_y writes around line 2517.

These are not necessarily player-character reads, but they must be reviewed before claiming full pure ECS position coverage for every entity type.

### Cause C - legacy factory routing bypass

Risk:

Any code that constructs or reuses CHARACTER without EntityFactory hydration can miss tags/components. This is the likely historical source of predicate fallback.

Required elimination action:

Inventory all CHARACTER creation/reuse paths and enforce one of:

- Route through EntityFactory.
- Call a post-create HydrateCharacterEntity(reg, ch, entity) hook.
- Assert in debug/test builds when a live character entity lacks the expected core components.

### Cause D - state-dependent behavior not modeled in ECS

Affected:

- PlayerRuntime::GetRaceNum: resolved in Phase 15E-60.9 via RaceState (baseRace + polymorphRace).
- PlayerRuntime::GetSectree: sectree service pointer is not modeled.
- AffectSystem::IsImmune: resolved in Phase 15E-60.9 via ImmunityFlags.
- CombatSystem alignment/PK/dead/stun/victim state wrappers.
- SkillSystem learn/use/hit/cooltime behavior wrappers.
- MountSystem riding/horse behavior wrappers.

Required elimination action:

Extend components before removing fallback. Examples:

- RaceState component: baseRace, currentRace, polymorphRace.
- SpatialPlacement/SectreeRef component or service query adapter.
- ImmunityFlags component.
- CombatState component: dead, stun, victim, alignment, PK mode.
- MountState read completion: riding, mountVnum, horse state.

### Cause E - accepted legacy-only behavior until later phases

Affected:

- ChatSystem output path.
- SocialSystem party/guild pointers.
- QuestSystem flags.
- Large parts of CombatSystem, SkillSystem, MountSystem, ItemSystem and GayaSystem.
- NetworkSyncSystem packet writes.

These are not good permanent ECS APIs, but they are outside the safe scope of a fallback cleanup pass. Treat them as explicit future migration phases, not accidental bugs.

## 7. Stat and affect sync audit

### Stats

PointSystem::GetGold/GetMaxHP/GetMaxSP/GetLevel are pure ECS and production-tested after the GetLevel int32_t hotfix.

Current architectural debt:

- PointSystem::Get/GetReal delegate only inside explicit SRC_LEGACY_ONLY mappings such as POINT_INVEN and POINT_GAYA.
- PointSystem::Change delegates to ch->PointChange(), so the write side still lives in legacy.
- CHARACTER::SetPoint and SetRealPoint now sync generic point writes into ECS mirrors.

Reason:

The 15C-1j lesson remains valid: POINT_* is not one flat storage class. It has true stat-array, virtual/live, and computed values. Removing the bridge before modeling this semantic split would risk damage, EXP, HP/SP and gold regressions.

Implemented component model:

- CharacterStatsComponent.points[type] for instant/live stat-array values.
- CharacterPoints.base.points[type] for real/base values.
- Dedicated live components for HP, SP, stamina, EXP, Gold and Level.
- Computed route for POINT_NEXT_EXP using Experience.next when populated, otherwise exp_table[level].
- SRC_LEGACY_ONLY branch for POINT_* values without ECS source yet; emits [POINT_LEGACY_ONLY] once per type.

### Affects

AffectSystem::FindAffect and IsAffectFlag read AffectList and are pure ECS.

Sync coverage:

- AddAffect, RemoveAffect, ClearAffect and RefreshAffect wrappers call SyncAffectList after legacy mutation.
- UpdateAffect periodically calls SyncAffectList.

Risks:

- Direct legacy mutation of m_list_pkAffect or m_afAffectFlag inside CHARACTER methods can bypass the mirror.
- LoadAffect and ProcessAffect contain direct list/flag work; verify SyncAffectList runs after all load/process transitions.

Recommended action:

Phase 15E-60.7 should add a focused audit/fix for every m_list_pkAffect and m_afAffectFlag write that does not go through the wrapper or does not call SyncAffectList.

## 9. Recommended phase structure

Phase 15E-60.6 - Predicate fallback removal

- Add/harden core entity hydration and invariant validation.
- Remove LegacyCharOf fallback from IsPC/IsNPC/IsStone/IsMonster.
- Keep behavior unchanged, but fail closed if tags are missing.

Phase 15E-60.7 - Scalar identity fallback removal

- Prove PlayerID, Empire, GMLevel, PacketVID and PlayerName are always populated.
- Remove fallback from GetPlayerID/GetEmpire/GetGMLevel/GetPacketVID/GetName.
- Add explicit sync/hydration at player load and descriptor attach if needed.

Phase 15E-60.8 - Generic POINT router

- Implemented ECS semantic router for PointSystem::Get/GetReal.
- Preserved 15C-1j semantic split: dedicated virtual/live, instant array, real/base array and computed next EXP.
- Removed ch->GetPoint/ch->GetRealPoint bridge for all non-SRC_LEGACY_ONLY point types.
- WinTest passed after 15E-60.8.
- Follow-up logger hotfix 7d54459 fixed a null string pointer in char_manager.cpp without changing ECS POINT behavior.

Phase 15E-60.9 - State extension pass

- Added RaceState for polymorph/current race and removed GetRaceNum legacy-first.
- Added ImmunityFlags and removed AffectSystem::IsImmune legacy read.
- Added SocialRefs and removed SocialSystem::GetParty/GetGuild legacy-only reads.
- Decide SectreeRef/service adapter strategy before removing GetSectree bridge.

Phase 15E-61+ - Service/behavior systems

- CombatSystem, SkillSystem, MountSystem, ItemSystem, GayaSystem, SocialSystem, QuestSystem and ChatSystem still contain large behavior bridges.
- These need domain-specific migrations, not a generic fallback cleanup.

## 10. Final architectural conclusion

Closest to target:

- Position reads.
- Gold/max HP/max SP/level reads.
- Affect flag/find reads.

Transitional but removable soon:

- Type predicates.
- Scalar identity getters.
- GetName.

Architectural debt that must not be hidden:

- GetDesc/GetSectree.
- PointSystem::Get/GetReal only for SRC_LEGACY_ONLY extensions (POINT_INVEN/POINT_GAYA).
- SocialSystem and QuestSystem accessors.
- Combat/Skill/Mount/Item/Gaya side-effect wrappers.

Target end state:

- ECS components are the single source of truth.
- Legacy CHARACTER is a transient compatibility cache.
- Legacy writes sync into ECS.
- ECS read APIs never call LegacyCharOf.
- Legacy side-effect adapters remain only where the subsystem itself has not yet been migrated, and they are documented as future phase boundaries.

## 12. Phase 15E-61.3 movement/warp write API update

Phase 15E-61.3 added entity-first movement write APIs in `ecs::MovementSystem`.

Status:

- `MovementSystem::Show` is a WRITE/SYNC BRIDGE. It writes Position/MapIndex/DirtyTag first, then calls legacy `CHARACTER::Show` for sectree registration, visibility and spawn packet behavior.
- `MovementSystem::WarpSet` is a WRITE/SYNC BRIDGE. It writes WarpPosition/DirtyTag first, then calls legacy `CHARACTER::WarpSet` for map-location validation and warp packet behavior.
- `MovementSystem::ExitToSavedLocation` is a WRITE/SYNC BRIDGE. It mirrors ExitPosition to WarpPosition before the legacy warp call and clears ExitPosition afterward.
- `MovementSystem::Goto` writes MovementDestination before legacy pathing behavior.
- `MovementSystem::Stop` clears MovementDestination before legacy idle-state behavior.
- `MovementSystem::Move` and `MovementSystem::OnMove` route through the existing legacy service path, which already syncs position into ECS via the 15E-59 hotfix pattern.

Caller-side migration result:

- `WarpSet`: 0 remaining CHARACTER caller-side calls.
- `ExitToSavedLocation`: 0 remaining CHARACTER caller-side calls.
- `Goto`: 0 remaining CHARACTER caller-side calls.
- `Stop`: 0 remaining CHARACTER caller-side calls; only non-CHARACTER `CSwitchbot::Stop` remains.
- `Move`: 0 remaining CHARACTER caller-side calls.
- `OnMove`: 0 remaining CHARACTER caller-side calls.
- `Show`: 0 remaining CHARACTER caller-side calls; only building object `Show` remains intentionally.

Architecture note:

- These APIs are not pure read accessors. Legacy calls inside the implementation are accepted service bridges because sectree registration, visibility tracking and packet broadcast are still legacy-owned.
- The invariant remains: ECS state is written first, and legacy service calls are compatibility side effects.
