## 3. LegacyItemOf / legacy item usage classification

Definitions found:

- `InventorySystem.cpp:38` local `LegacyItemOf(entt::entity)` resolves `ItemIdentity.id` through `ITEM_MANAGER`.
- `ItemSystem.cpp:372` local `LegacyItemOf(entt::entity)` resolves `ItemIdentity.id` through `ITEM_MANAGER`.
- `ItemSystem_LegacyBridge.cpp:359` local `LegacyItemOf(entt::entity)` mirrors the same pattern inside the explicit legacy bridge file.

Wrapper helpers in `ItemSystem.cpp`:

- `ResolveLegacyItemForSync` - WRITE/SYNC BRIDGE.
- `ResolveLegacyItemForLegacySideEffect` - mixed use; acceptable for side effects, not acceptable for read accessors long-term.
- `ResolveLegacyItemForDestruction` - WRITE/SYNC BRIDGE.

Read accessor fallback/debt sites:

- Post 15E-65.3: proto-derived accessors read `ItemProtoRef`; no legacy-only proto read remains.
- Post 15E-65.4: `GetItemFlags`, `GetItemOwner`, `GetItemAttribute`, `GetItemWindow`, `GetItemCell`, and `IsItemEquipped` no longer call legacy fallback.
- Composed location predicates (`IsItemInInventory`, `IsItemInExtraInventory`, `IsItemInDragonSoulInventory`) now compose through pure `GetItemWindow`.

Legitimate bridge sites:

- `ItemSystem.cpp:1532+` count mirroring writes ECS first and mirrors to legacy.
- `ItemSystem.cpp:1688+` socket writes ECS and legacy.
- `ItemSystem.cpp:1736+` attribute writes ECS and legacy.
- `ItemSystem.cpp:1825+` exchanging/lock/skip-save/window/cell writes ECS and legacy.
- `ItemSystem.cpp:2011+` place/remove/equip/unequip bridge through legacy inventory service behavior.
- `ItemSystem.cpp:2186+` explicit `SyncItem*FromLegacy` paths.
- `ItemSystem_LegacyBridge.cpp` is intentionally named as an accepted bridge boundary.

## 4. Item entity creation audit

Canonical item entity factory:

- `EntityFactory::CreateItemEntity` at `SRC/Server/GameServer/ecs/EntityFactory.cpp:640`.
- Existing item entity is found by `CItemRegistry::Instance().Find(itemID)`.
- Existing entity is re-synced through `SyncItemEntity`.
- New entity is created, fully synchronized, then registered in `CItemRegistry`.

Factory-populated components:

- `ItemIdentity`
- `ItemLocation`
- `ItemCount`
- `ItemPrototypeMeta`
- `ItemOwner`
- `ItemEquipped`
- `ItemFlags`
- `ItemSockets`
- `ItemAttributes`

Creation risk:

- No obvious missing component population was found in `CreateItemEntity`.
- The main Cause A/C risk is not the factory itself. It is direct `ITEM_MANAGER::CreateItem` usage where the caller forgets to call `EntityFactory::CreateItemEntity` after creating/loading the legacy item.
- Many call sites already call `EntityFactory::CreateItemEntity(g_registry, item)` immediately after `ITEM_MANAGER::CreateItem`, but this should be enforced with an invariant in 15E-65.1.

## 5. Item write path sync audit

Write-site scan found direct legacy item writes outside ECS systems, especially:

- `item_manager.cpp`: many `SetSocket` and one `SetCount` around item creation/load paths.
- `cmd_gm.cpp`: direct item creation and socket/count setup paths.
- `questlua_pc.cpp`: direct item creation and socket setup paths.
- `safebox.cpp`, `shop.cpp`, `shopEx.cpp`, `shop_manager.cpp`: create/move/consume item paths using `EntityFactory::CreateItemEntity` in several locations.

Current mitigation:

- `CreateItemEntity` re-syncs the full item component state from legacy whenever called.
- Many write paths call ItemSystem wrappers (`SetItemSocket`, `SetItemCount`, `SetItemAttribute`), which are ECS-first and mirror to legacy.

Remaining risk:

- Direct legacy item writes remain a general bridge risk, but 15E-65.2 added sync for the identified stale attribute path and the 15E-65.4 target reads now rely on ECS state only.
- Any new missing/stale component issue should surface via item invariants or gameplay regression; read fallback must not be restored.

## 6. Cause classification

| Cause | Applies | Evidence | Fix direction |
|-------|---------|----------|---------------|
| Cause A - component not populated | Limited | Factory populates all current components. Risk only if creation bypasses `CreateItemEntity`. | Add item hydration invariant and factory audit. |
| Cause B - stale write sync | High | Direct legacy `SetSocket/SetCount/...` writes exist outside ECS systems. | Convert write sites to ItemSystem wrappers or add sync hooks. |
| Cause C - legacy creation bypass | Medium | Many `ITEM_MANAGER::CreateItem` call sites exist; most but not all need verification. | Route all creation through `EntityFactory::CreateItemEntity` or add post-create invariant. |
| Cause D - state not modeled | High | Proto-derived reads still call `LPITEM`: value, name, size, refine, flags, proto. | Add `ItemProtoRef` / extended `ItemPrototypeMeta` / `ItemRuntimeFlags` components. |
| Cause E - accepted legacy service behavior | Medium | DSManager, ITEM_MANAGER destruction, inventory service behavior remain legacy-owned. | Keep as explicit WRITE/SYNC BRIDGE until item service phases. |

## 7. Bucket breakdown

Bucket 1 - Component population fixes:

- Add `ItemProtoRef` or full proto-derived component coverage.
- Add missing runtime flag fields if needed: wear flags, anti flags, immune flags, refined vnum, refine level, size, level limit, timer limit.
- Estimated sites: 1 factory plus 10-12 accessor mappings.
- Effort: 1-2 days.
- Risk: low/medium because read behavior changes must match proto semantics exactly.

Bucket 2 - Sync at write site:

- Replace direct `LPITEM->SetSocket`, `SetCount`, `SetAttributes`, location/owner/equipped mutations with ItemSystem APIs or explicit `SyncItemStateFromLegacy`.
- Estimated sites: 25-40 candidate write sites after filtering false positives.
- Effort: 2-4 days.
- Risk: medium because item load/create/shop/safebox paths are gameplay/economy critical.

Bucket 3 - Factory routing:

- Enforce `ITEM_MANAGER::CreateItem` -> `EntityFactory::CreateItemEntity` pairing.
- Add invariant logging for CItem with nonzero ID and no `CItemRegistry` entity.
- Estimated sites: 10-20 creation paths.
- Effort: 2-3 days.
- Risk: medium/high due to quest, GM, shop, safebox, drop and item manager paths.

Bucket 4 - Component extension:

- Model proto fields and item runtime flags currently read through `LPITEM`.
- Convert `GetItemValue`, `GetItemName`, `GetItemSize`, `GetItemRefineVnum`, `GetItemRefineLevel`, `GetItemLevelLimit`, `GetItemWearFlags`, `GetItemAntiFlags`, `GetItemImmuneFlags`, `GetItemProto`.
- Estimated accessors: 10.
- Effort: 2-3 days.
- Risk: low if component data is copied directly from proto and validated with logs.

Bucket 5 - Accepted debt:

- `ItemSystem_LegacyBridge.cpp` remains accepted bridge debt.
- DSManager operations in `DragonSoulSystem` remain accepted service debt.
- ITEM_MANAGER remove/destroy and legacy inventory service calls remain accepted write-side service bridges until a full item service phase.

## 8. Recommended 15E-65.x phase structure

Phase 15E-65.1 - Item factory and invariant coverage:

- Add item invariant helper: valid item entity must have `ItemIdentity`, `ItemLocation`, `ItemCount`, `ItemPrototypeMeta`, `ItemOwner`, `ItemFlags`, sockets and attrs.
- Add one-time warning for `LPITEM` with nonzero ID but missing `CItemRegistry` entity.
- Verify all `ITEM_MANAGER::CreateItem` paths hydrate via `EntityFactory::CreateItemEntity`.
- Estimated effort: 1-2 days.

Phase 15E-65.2 - Item write sync cleanup:

- Migrate direct `SetSocket/SetCount/SetAttributes/location/flag` writes to ItemSystem wrappers.
- Add sync at unavoidable legacy write sites.
- Do not remove read fallbacks until this phase passes WinTest.
- Estimated effort: 2-4 days.

Phase 15E-65.3 - Proto-derived component extension:

- Add `ItemProtoRef` or expanded `ItemPrototypeSnapshot`.
- Populate at `CreateItemEntity`.
- Convert proto-derived read accessors to pure ECS.
- Estimated effort: 2-3 days.

Phase 15E-65.4 - Remove read fallback:

- Completed: removed legacy fallback from `GetItemFlags`, `GetItemOwner`, `GetItemAttribute`, `GetItemWindow`, `GetItemCell`, and `IsItemEquipped`.
- Completed by 15E-65.3: removed legacy-only reads for proto-derived accessors through `ItemProtoRef`.
- Result: item read accessors are now pure ECS; remaining legacy item use is explicit write/service bridge code.

Phase 15E-65.5 - Explicit accepted debt close-out:

- Document remaining service bridges: ITEM_MANAGER destruction, DSManager, legacy inventory side effects.
- Keep these bridges named and isolated, not hidden inside read accessors.

## 10. Architectural conclusion

The item layer is ahead of the old CHARACTER layer in some places:

- Item identity, count, sockets, attributes, basic location and equipped state already have ECS components.
- `CreateItemEntity` hydrates a complete current item component set.
- Several caller-facing reads are already ECS-first or pure ECS.

Post 15E-65.4 item read state:

- PURE ECS reads: 42.
- ECS-FIRST + FALLBACK reads: 0.
- LEGACY-ONLY reads: 0.
- Remaining legacy item usage is write/sync or service bridge debt, not hidden read fallback.

Recommended rule for 15E-65.x:

- Do not remove fallbacks blindly.
- First prove creation hydration and write-side sync.
- Proto-derived state now lives in `ItemProtoRef`.
- Read fallback is removed; missing item component issues must be fixed at source.
- Keep bridge boundaries explicit until the later item service/CItem deletion phases.
