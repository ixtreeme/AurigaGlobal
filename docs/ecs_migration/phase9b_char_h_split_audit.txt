Step 7 - Proposed split layers
------------------------------
Layer 1 - char_fwd.hpp
  - Contents: forward declaration of CHARACTER plus LPCHARACTER alias only.
  - Immediate candidate files from Phase 9 snapshot: 12
Layer 2 - char_interface.hpp
  - Contents: public CHARACTER method declarations only, includes char_fwd.hpp.
  - Immediate candidate files from Phase 9 snapshot: 68
Layer 3 - char.h (shrunk full definition)
  - Contents: full class definition, private/protected members, friend declarations, event handles, internal state.
  - Files that must remain here initially from Phase 9 snapshot: 49
Blocking factors for Layer 3 reduction:
  - 1474 private-member access lines remain in ecs/systems/*.cpp.
  - 26 direct LPEVENT member declarations remain on CHARACTER and must stay until legacy event scheduling is removed.
  - CHARACTER point/state/storage internals (m_points, m_pointsInstant, networking state, sync state, event maps, pet/mount/fishing/combat/runtime fields) are still read directly by L3 users.

Step 9 - Audit conclusion
-------------------------
The split is mechanically feasible, but char.h cannot shrink to an interface-only header yet.
The first safe cut is Layer 1: move LPCHARACTER out of typedef.h into a dedicated forward-only header and migrate the L1 snapshot set first.
Layer 2 can follow once current L2 files are revalidated against today's tree and method-only includes are switched over.
Layer 3 remains blocked by private field access and the legacy event-handle surface still embedded in CHARACTER.
