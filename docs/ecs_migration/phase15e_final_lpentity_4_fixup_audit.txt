Phase 15E-final.LPENTITY.4-fixup - Movement state ECS sync audit
================================================================

Scope
-----

Audit-only phase. No source code changes were made. This report documents the
legacy CHARACTER write paths that bypass the parallel ECS components consumed
by the native EntityNetworkDispatch::SendCharacterInsert builder, and is the
prerequisite of the 4-fixup.1-5 implementation work.

Background
----------

Phase 15E-final.LPENTITY.4 (3b74ef3) made character view-packet dispatch native
through ecs::EntityNetworkDispatch::SendInsert / SendRemove. Two-client testing
revealed character position divergence: client A and client B saw the same two
characters at different relative distances. Two hotfixes followed:

- 2caa410 - BroadcastToView reverted to legacy GetViewersOf (ViewerMap mirror
  lag - out of scope for this fixup).
- 21dc2df - EntityNetworkDispatch::SendInsert / SendRemove for SpatialKind
  ::Character calls back into legacy CHARACTER::EncodeInsertPacket /
  EncodeRemovePacket (temporary).

Root cause: native BuildCharacterInsert reads ECS Position, MovementDestination,
MovementState, and StatusFlags. Legacy EncodeInsertPacket reads m_posDest,
m_dwMoveStartTime, m_dwMoveDuration, m_bNowWalking, m_bAddChrState, and
m_afAffectFlag. Several legacy write sites do not have a matching ECS component
update, leaving the ECS side stale. Native dispatch then encodes from stale
state while legacy encodes from fresh state, producing different on-the-wire
bytes for the same observed character.

This audit lists every divergent write path so 4-fixup.2 can add the missing
sync.

-------------------------------------

isSpawnState / isKillerMode / isPartyState feed the same field in native via
StateFlagsFor (services/EntityNetworkDispatch.cpp:104-120). Discrepancy
between the two sides produces a different bStateFlag byte even when position
state is in sync.

Rotation audit (clean)
----------------------

Native: BuildCharacterInsert reads RotationComponent::yaw with fallback to
CharacterRuntimeFlagsComponent::rotation
(services/EntityNetworkDispatch.cpp:80-87).

Legacy: EncodeInsertPacket reads GetRotation() which returns
runtime->rotation (ecs/systems/MovementSystem.cpp:999-1004).

Single writer for both ECS sources: SetRotation @
ecs/systems/MovementSystem.cpp:448-455 updates runtime->rotation (line 449)
and rotation->yaw (line 454) atomically.

Single writer for RotationComponent::yaw: line 454 only. No other writer.

Conclusion: rotation is consistent. No fix needed.

KASMIR shop sign audit (drift)
------------------------------

Build flag: KASMIR_PAKET_SYSTEM is defined at common/service.h:66 - active in
this build.

Legacy: NetworkSyncSystem.cpp:1041 sets pack.bShopKasmirTitle =
m_bKasmirPaketBaslik when KASMIR is active.

Native: services/EntityNetworkDispatch.cpp:234-235 hard-codes
sign.bShopKasmirTitle = false.

Drift: confirmed when m_bKasmirPaketBaslik is true. The native builder will
produce a packet with bShopKasmirTitle = false while legacy produces true.

This is a single packet field, only emitted when the source character has an
active shop. To fix in 4-fixup.2.g, add a KasmirShopFlag component populated at
the legacy m_bKasmirPaketBaslik write site, and read in the native shop sign
emission path at EntityNetworkDispatch.cpp:234. Alternative: extend the
existing ShopState component with a kasmirTitle flag.

Test matrix for 4-fixup.4 / 4-fixup.5
-------------------------------------

WinTest scenarios required to gate native re-enable (4-fixup.5). Each scenario
must produce zero [MOVEMENT_DRIFT], [INSERT_PARITY], [VIEWMAP_DRIFT],
[BROADCAST_DRIFT], [DISPATCH_FALLBACK], or [SPATIAL_INVARIANT] warnings in
syslog.txt. Visual verification: both clients see both characters at
identical relative positions.

1. Two clients in mutual view, both walk - run mode toggle.
2. Mount, unmount, mount-while-moving.
3. Third client logs in while character A is mid-move, observes character A
   from spawn.
4. Stun affects character mid-walk - dest reset path.
5. Map warp - viewer crosses map boundary, sees re-encoded characters.
6. Observer mode toggle on / off, viewer re-encodes existing view set.
7. Character death and respawn.
8. Drift-injection negative test: temporary commit that bypasses one of the
   Sync*Write helpers and writes a legacy field directly. Run scenario 1.
   Verify [MOVEMENT_DRIFT] warning fires for the affected entity. Revert the
   temporary commit before continuing.

Failure of the negative drift-injection test means the detector is placebo
and 4-fixup.5 must not proceed.

Summary
-------

5 movement drift sites + 4 m_bAddChrState drift sites + 2 StatusFlags reverse
drift sites + 1 KASMIR drift site = 12 confirmed write paths requiring sync.

Phase 4-fixup.2 adds Sync*Write helper calls at the 5 movement sites
(commits 2.a-2.e). Phase 4-fixup.2.f covers state flags. Phase 4-fixup.2.g
covers KASMIR. Phases 4-fixup.3 and 4-fixup.4 add a runtime drift detector
and packet byte-parity verifier that prove parity before phase 4-fixup.5
re-enables native character dispatch.
