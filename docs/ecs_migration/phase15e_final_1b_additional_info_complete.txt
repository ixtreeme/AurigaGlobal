# Phase 15E-final.1b - Native Additional Info / Rank Title Path

Date: 2026-05-03
Build target: `GameServer` / `RelWithDebInfo`.

## 1. Packets Rewritten Natively

Rewritten packet construction:

- `TPacketGCCharacterAdditionalInfo`
- `HEADER_GC_CHAR_ADDITIONAL_INFO`

New native ECS functions:

- `NetworkSyncSystem::BuildCharAdditionalInfo(entt::registry&, entt::entity, TPacketGCCharacterAdditionalInfo&)`
- `NetworkSyncSystem::SendCharAdditionalInfo(entt::registry&, entt::entity source, entt::entity recipient)`
- `NetworkSyncSystem::BroadcastCharAdditionalInfo(entt::registry&, entt::entity source)`

The packet builder reads from ECS state:

- `VIDComponent`
- `PlayerName`
- `EmpireComponent` via `PlayerRuntime`
- `CombatStats.alignment`
- `CombatStats.pkMode`
- `AppearancePartsComponent`
- `SkillColor`
- `LevelComponent` via `PointSystem`
- `MountState` via `MountSystem`
- `SocialRefs` via `SocialSystem`
- `NetworkSession` language via `NetworkService`
- `PetComponent.level` for new pet level where available

## 2. Alignment / Rank Refresh

`CHARACTER::UpdateAlignment` no longer calls the full legacy `UpdatePacket()` for visible alignment changes.

It now calls:

```cpp
NetworkSyncSystem::BroadcastCharAdditionalInfo(g_registry, AIHelpers::EcsOf(this));
```

This narrows the real-time rank/title refresh to the additional-info packet that actually carries `sAlignment`.

## 3. Sync Fixes Added

The native packet reads `CombatStats.pkMode`, so legacy PK mode writes now sync that component:

- `CHARACTER::SetPKMode`
- player load / GM protection paths that assign `m_bPKMode`
- mob setup path that assigns `m_bPKMode`
- reset path that assigns `m_bPKMode`

## 4. CHARACTER:: Bodies Deleted

No full `CHARACTER::` body was deleted in this sub-phase.

Reason:

- There is no standalone `CHARACTER::SendCharAdditionalInfo` body.
- The packet construction was embedded inside `CHARACTER::EncodeInsertPacket` and `CHARACTER::UpdatePacket`.
- Deleting those bodies requires the full spawn/update packet rewrite planned for 15E-final.1c/1d.

## 5. char.h Declarations Removed

None.

No standalone declaration existed for the additional-info packet sender.

## 7. Broadcast Path Status

Broadcast remains a temporary service boundary:

- `BroadcastCharAdditionalInfo` builds the packet from ECS.
- Visibility iteration still uses legacy `PacketAround` through a `CHARACTER_MANAGER` lookup.
- This is explicitly deferred to Phase 15E-final.1d, where the ECS visibility service replaces `m_map_view` / `PacketAround`.

This is not read fallback: packet state is ECS-native; only recipient selection remains a legacy service boundary.
