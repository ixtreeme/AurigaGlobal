Step 3 - Public inline getters returning private members
- Query:
  grep -cE "return\s+m_[a-zA-Z]" SRC/Server/GameServer/char.h
- Result: 145

Interpretation
- 145 public inline getters directly expose private member state through `return m_*`.
- These are the main blockers for converting char_interface.hpp into a true public-only declaration header while keeping char.h private-state-only.
- They are also the best first extraction batch, because they are mostly declaration-only candidates once their bodies move out of the header.

Extraction risk summary
- Best safe first wave: Tier A
  Rationale: mostly direct getters/setters and small accessors.
- Second wave: Tier B
  Rationale: still short, low fanout risk, usually no extra helper surface.
- Deferred wave: heuristic misses
  The current script likely under-detects multi-line, nested-brace, or unusual-signature inline bodies.
  Before actual extraction begins, re-audit with a parser that can handle nested braces or use a targeted line-by-line/manual inventory for the remaining non-moved methods.

Proposed extraction order
1. Tier A first
   - bulk move trivial getters/setters and declaration-only accessors out of char.h
2. Tier B second
   - batch-move short logic methods in small compile-safe groups
3. Remaining unmatched / residual bodies
   - inspect manually; these are the real Tier C candidates in practice
4. Template / lambda cases
   - keep inline unless a specific restructuring need appears

Recommended next action for Phase 9d implementation
- Start with the 145 `return m_*` public getters.
- Split them into batches of 20-30 methods.
- After each batch:
  - move definitions out of char.h
  - keep declarations in char_interface.hpp
  - build gate
- Only after the getter batch is stable, continue with Tier B one-liners and short helpers.

Bottom line
- Current tree state supports a practical extraction-first strategy.
- The real low-risk starting set is large: 145 direct `return m_*` public getters and a broader Tier A pool of 166 methods.
- The legacy `309` inline estimate is no longer current for this tree; use 266 signature hits / 264 classified bodies as the live baseline.
