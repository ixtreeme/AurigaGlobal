## CHARACTER Field Classification

### M1 - Already Mirrored in ECS

These fields have ECS components/accessors and should not block deletion once legacy method bodies stop owning behavior.

| Legacy field group | ECS state / system |
|--------------------|--------------------|
| `m_dwPlayerID`, `m_stName`, VID, empire, GM level | identity components and `PlayerRuntime` |
| type/race/polymorph fields such as `m_bCharType`, `m_dwPolymorphRace` | type tags and `RaceState` |
| `m_x`, `m_y`, map index / spatial placement | `Position`, `MapIndex`, spatial placement components |
| HP/SP/stamina/gold/level/EXP/points | `Health`, `Mana`, vital/stat components, `PointSystem`, `PointRouter` |
| affects and immunity flags | `AffectSystem`, affect mirror, `ImmunityFlags` |
| party/guild pointers | `SocialRefs` |
| inventory/equipment readable state | inventory components plus item entity state |
| mount/pet state already accessed via ECS helpers | mount/pet runtime components |
| alignment/rank title runtime data | alignment sync paths and network update packets |

### M2 - Needs New or Expanded ECS Components

These fields still represent deletion blockers unless they are moved into explicit ECS-owned state.

| Legacy field group | Required ECS modeling |
|--------------------|----------------------|
| refine state: `m_bUnderRefine`, `m_dwRefineNPCVID`, `m_iRefineAdditionalCell`, refine item references | `RefineSession` component |
| shop/private shop state: `m_pkShop`, `m_pkMyShop`, shop sign/title fields | `ShopSession` / `PrivateShopState` component |
| exchange/trade transient state where still pointer-bound | explicit `ExchangeRef` lifecycle validation |
| quest NPC/session state such as quest NPC VID/id | `QuestInteractionState` component |
| sync ownership and movement sync owner lists | `MovementSyncOwnership` component |
| fly target vector and combat target caches | `CombatTargetState` extension |
| combo and attack-pulse state | `CombatTimingState` extension |
| AI state-machine timers and event pointers | ECS event/state-machine component |
| activity runtime for fishing/mining | `ActivityState` extension |
| dungeon ticket/event flags and dungeon membership details | dungeon/service ref component |
| mobile/auth/chat/mount anti-spam counters | rate-limit/cooldown components |

### M3 - Service Pointer / Accepted External Debt

These are not pure entity state. They should be isolated behind service abstractions rather than copied blindly into ECS.

| Legacy pointer/state | Reason |
|----------------------|--------|
| `m_pkDesc` | network session service pointer |
| `m_pSectree` | spatial service pointer |
| dungeon/shop/exchange service pointers | server service objects with external lifecycle |
| event pointers | event scheduler service handles |
| descriptor/packet/view-map dependencies | network service compatibility |
| DB/save related service paths | persistence compatibility |

`GetDesc` and `GetSectree` remain accepted E-class debt for now. They are service pointers, not gameplay state.

### M4 - Internal Cache / Transient Fields

These should either be deleted with their method body, or moved only if the subsystem still needs them after extraction.

Examples:

- movement timing: `m_dwMoveStartTime`, `m_dwMoveDuration`, `m_dwLastMoveTime`, `m_dwWalkStartTime`, `m_dwStopTime`
- combat timing: `m_dwLastAttackTime`, combo counters, attack-pulse fields
- anti-spam/rate-limit counters: shout/chat/mount counters
- skip-save/load flags
- temporary vectors/maps such as damage maps or fly target lists
