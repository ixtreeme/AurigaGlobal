1. EntityNetworkDispatch

Added:
  - SRC/Server/GameServer/ecs/services/EntityNetworkDispatch.hpp
  - SRC/Server/GameServer/ecs/services/EntityNetworkDispatch.cpp

Primary API:
  - EntityNetworkDispatch::SendInsert(reg, sourceE, viewerE)
  - EntityNetworkDispatch::SendRemove(reg, sourceE, viewerE)
  - EntityNetworkDispatch::Reencode(reg, viewerE)

Dispatch source:
  - SpatialKind::Character -> native character insert/remove packet
  - SpatialKind::Item -> native ground item insert/remove packet
  - SpatialKind::Building -> native building insert/remove packet
  - SpatialKind::OfflineShop -> native offline shop insert/remove packet

2. Native packet builders

Character:
  - Builds TPacketGCCharacterAdd from ECS components.
  - Uses CharacterType, VIDComponent, Position, RaceState, RotationComponent, AffectList, StatusFlags, MovementDestination, MovementState, ShopState.
  - Sends additional info via existing native NetworkSyncSystem::SendCharAdditionalInfo.

Item:
  - Builds ground add/remove packets from ItemIdentity and ItemGroundPosition.
  - Sends ownership packet from ItemOwnershipDisplay.

Building:
  - Builds legacy-compatible TPacketGCCharacterAdd with CHAR_TYPE_BUILDING.
  - Reads BuildingState, VIDComponent, Position.

OfflineShop:
  - Builds TPacketGCNewOfflineshop insert/remove payloads.
  - Reads OfflineShopState and Position.
  - NetworkService gained SendBufferedPair for header + subpacket compatibility.

  - OfflineShopState::name: required by native shop entity insert packet.

Population:
  - EntityFactory::CreatePC -> CharacterType{CHAR_TYPE_PC}
  - EntityFactory mob/NPC/stone path -> CharacterType{TMobTable.bType}
  - OfflineShop create/update paths sync OfflineShopState name/race/type.

4. entity_view.cpp dispatch replacement

entity_view.cpp normal packet path now calls:
  - DispatchInsert -> EntityNetworkDispatch::SendInsert
  - DispatchRemove -> EntityNetworkDispatch::SendRemove

Affected paths:
  - ViewInsert
  - ViewRemove
  - ViewReencode
  - UpdateSectree stale view removal
  - Observer mode view transitions

Fallback:
  - Virtual EncodeInsertPacket / EncodeRemovePacket is called only if source or viewer cannot be mapped to entt::entity.
  - Fallback emits [DISPATCH_FALLBACK].
  - Runtime target: [DISPATCH_FALLBACK] count must be zero.

5. BroadcastToView status

Initial LPENTITY.4 state:
  - NetworkService::BroadcastToView used VisibilityService::GetViewersOfNative.

Hotfix state:
  - BroadcastToView is restored to VisibilityService::GetViewersOf as authoritative.
  - Native ViewerMap remains a drift-checked mirror, not the production recipient source.
  - Reason: under two-client movement load, native ViewerMap could lag/stale enough to produce multi-second visible sync divergence.

Debug drift guard:
  - Compares native viewer count to authoritative ViewersOf result in non-NDEBUG builds.
  - Emits [BROADCAST_DRIFT] if sizes differ.
  - BroadcastToView(false) now avoids double-sending to source if the authoritative recipient set already contains source.

6. Virtual wrapper status

  - building::CObject::EncodeInsertPacket / EncodeRemovePacket now forward to EntityNetworkDispatch.

Legacy bodies remain present until LPENTITY.6. Character insert/remove is intentionally active until native movement destination/state parity is proven.

10. Hotfix: Restore character view packets

Commit:
  - 21dc2df Hotfix LPENTITY.4: Restore character view packets

Runtime issue:
  - Two clients could see the same two characters at different distances/positions.
  - One client showed the characters next to each other while the other showed them far apart.
  - Prior BroadcastToView authoritative-recipient hotfix did not resolve the issue.

Root-cause assessment:
  - The remaining divergent path was character view insertion/removal after LPENTITY.4.
  - EntityNetworkDispatch::SendCharacterInsert builds character add/move packets from ECS Position, MovementDestination, and MovementState.
  - Legacy CHARACTER::EncodeInsertPacket still owns the exact historical movement state semantics: m_posDest, m_dwMoveStartTime, m_dwMoveDuration, m_bNowWalking.
  - If ECS movement destination/state is stale or not identical for every movement path, a viewer can receive an insert packet with a position that differs from the legacy-authoritative state.

Fix applied:
  - EntityNetworkDispatch::SendInsert for SpatialKind::Character resolves LPENTITY at the SpatialService boundary and calls CHARACTER::EncodeInsertPacket.
  - EntityNetworkDispatch::SendRemove for SpatialKind::Character resolves LPENTITY at the SpatialService boundary and calls CHARACTER::EncodeRemovePacket.
  - CHARACTER::EncodeInsertPacket / EncodeRemovePacket no longer recursively call EntityNetworkDispatch first.
  - Item, Building, and OfflineShop native dispatch remains active.
  - BroadcastToView(false) duplicate self-send guard added.

Architectural status:
  - This is an intentional temporary rollback for character spawn/remove packet authority only.
  - It does not revert LPENTITY.4 globally.
  - Native character insert can be retried after a focused movement parity audit:
    - ECS MovementDestination must match legacy m_posDest.
    - ECS MovementState::moveStartTime / moveDuration must match m_dwMoveStartTime / m_dwMoveDuration.
    - Walking mode must match m_bNowWalking on every movement path.
