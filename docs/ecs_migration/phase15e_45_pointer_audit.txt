## 5. Roadmap

Tier 1 - GAME ENTITY migration:
- Finish `LPCHARACTER` and `LPITEM` public/API cleanup, then collapse remaining bridge/core islands.
- Convert `LPENTITY` generic world APIs after concrete character/item paths are stable.
- Convert `LPOBJECT`/building-object flows to entity + components after `LPENTITY` is no longer public-facing.

Tier 2 - SERVICE OBJECT signatures:
- Refactor `CParty`, `CShop`/`CShopEx`, and `CDungeon` APIs to accept `entt::entity` for actors/items while keeping the service objects themselves as C++ classes.
- Avoid converting party/shop/dungeon classes themselves into entities unless they need world position/lifecycle semantics.

Tier 3 - INFRASTRUCTURE:
- Keep `DESC`, `CLIENT_DESC`, `DESC_P2P`, buffers, fdwatch, heart, and logfile as infrastructure/RAII wrappers.
- Migrate `LPEVENT` separately to a Flecs/ECS scheduler or central `EventSystem`; do not mix with gameplay entity migration.

Tier 4 - DATA STRUCTURE:
- Keep `SECTREE`, `SECTREE_MAP`, `SECTREE_LIST`, `regen`, and regen exception structures as data structures initially.
- Add entity-facing adapter APIs where gameplay code currently passes `LPENTITY`/`LPCHARACTER` into spatial or spawn systems.

## 6. Recommended next phases

| Phase | Focus | Exit criteria |
|---|---|---|
| 15E-46 | Complete `LPCHARACTER` API cleanup | Public gameplay systems accept `entt::entity`; legacy char pointer bridge isolated. |
| 15E-47 | Complete `LPITEM` read/core island cleanup | Caller-side CItem reads gone outside core/bridge; ItemManager lookup remains internal only. |
| 15E-48 | `LPENTITY` generic world API migration | `CEntity*` no longer used as public gameplay handle; sectree/view dispatch accepts entity ids. |
| 15E-49 | `LPOBJECT` building/world object migration | Building/object flows represented as entities/components or isolated service data. |
| 16A | Party service entity-first signatures | Party membership APIs use `entt::entity` for players. |
| 16B | Shop/shopEx service entity-first signatures | Shop transactions use entity ids for actor/item boundary APIs. |
| 16C | Dungeon service entity-first signatures | Dungeon APIs expose entity-based actor/item operations. |
| 17A | Descriptor/session boundary cleanup | Network descriptors remain infra; session components map descriptors to character entities. |
| 17B | Event scheduler migration | `LPEVENT` use replaced or isolated behind ECS/Flecs scheduler facade. |
| 18A | Sectree adapter pass | Spatial APIs become entity-facing without deleting sectree structures. |
| 18B | Regen adapter pass | Spawn configs stay data; spawn outputs are entities. |

## 7. Conclusion

Full EnTT cannot be claimed with only `LPCHARACTER` and `LPITEM` migrated. The next mandatory gameplay handles are `LPENTITY` and `LPOBJECT`; service objects (`LPPARTY`, `LPSHOP`, `LPDUNGEON`) should keep their classes but become entity-first at API boundaries. Infrastructure aliases should not be blindly converted to `entt::entity`; especially `LPEVENT` needs a dedicated scheduler design.
