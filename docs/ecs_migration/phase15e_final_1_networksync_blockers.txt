# Phase 15E-final.1 - NetworkSyncSystem Native ECS Rewrite Status

Date: 2026-05-03
Mode: safe implementation slice plus blocker inventory.
Build target: `GameServer` / `RelWithDebInfo`.

## 1. Requested Target

Requested final state:

- `NetworkSyncSystem.cpp` contains zero `LPCHARACTER`.
- `NetworkSyncSystem.cpp` contains zero `LegacyCharOf`.
- `NetworkSyncSystem.cpp` contains zero `CHARACTER::` method bodies.
- Packet construction reads ECS components directly.
- Descriptor access is hidden behind `ecs::NetworkService`.

This target is not safe to complete in one mechanical pass because several packet bodies still read legacy-only packet state that is not yet represented as ECS components.

## 2. Implemented in This Slice

Added `ecs::NetworkService` service boundary:

- `ecs::NetworkService::Send(entt::entity recipient, const void* packet, size_t size)`
- `ecs::NetworkService::Broadcast(entt::registry& reg, entt::entity source, const void* packet, size_t size, int range)`
- `ecs::NetworkService::SendToAll(const void* packet, size_t size)`

`Broadcast` is intentionally conservative in this slice: it logs a one-time warning and does not send until the ECS visibility service exists. A global send-all implementation would be packet-semantics corruption.

Migrated the already-native dirty update loop in `NetworkSyncSystem_Update`:

- Removed the local `LegacyCharOf(entity)` lookup.
- Removed direct descriptor packet send from the update loop.
- Sends `TPacketGCMove` and `TPacketGCPoints` through `ecs::NetworkService::Send`.
- Clears `DirtyTag` only after a successful send, so missing descriptors do not silently drop pending updates.

This is Phase 15E-final.1a, not the full final.1 target.

## 5. Missing Components / Services

Required before a true zero-legacy rewrite:

- `NetworkService::Broadcast` must implement actual visibility/range semantics, not a global send-all fallback.
- `ViewMapService` or equivalent ECS visibility index must replace `m_map_view`.
- `AffectPacketFlags` or packet-ready affect flag component must replace direct `m_afAffectFlag` packet reads.
- `MovementPacketState` must model destination, start position, duration, start time and walking mode.
- `RuntimePacketState` must model `m_bAddChrState` and related packet bits.
- `ShopSignState` must model shop sign and Kasmir/fake-shop title state.
- `ItemTitlePrefixState` must model item title prefix and last-sent cache.
- `SyncOwnership` must model sync owner and owned list.
- `ItemNetworkState` must model item ground/owner/network update fields used by `CItem::` packet bodies.
- Party/guild packet snapshots need service boundaries where party/guild remain non-ECS services.

## 6. Recommended Phase Split

Recommended continuation:

1. Phase 15E-final.1a - NetworkService boundary and dirty update loop native send. Completed in this slice.
2. Phase 15E-final.1b - Native additional-info / rank-title packet path.
3. Phase 15E-final.1c - Native `MainCharacterPacket`, `UpdatePacket`, and `PointsPacket`.
4. Phase 15E-final.1d - ECS visibility service and native spawn/remove/effect broadcast.
5. Phase 15E-final.1e - Native equipment packet builder.
6. Phase 15E-final.1f - Item network packet extraction from `CItem::` bodies.
7. Phase 15E-final.1g - Delete remaining `CHARACTER::` / `CItem::` network packet bodies and declarations.

## 7. Architectural Conclusion

The strict zero-legacy target is correct, but forcing it before the missing packet state exists would only move legacy behavior behind wrappers or break packet semantics.

The safe path is staged:

- Add service boundaries first.
- Move packet bodies only when every field they read is available from ECS or an explicit service snapshot.
- Delete legacy bodies only after caller counts reach zero and packet parity is verified by WinTest.
