# Phase 15E-final.0.5 - Dead Method Body Categorization

Date: 2026-05-02
Scope: identify legacy `CHARACTER::` / `CItem::` method bodies that can be deleted safely.
Mode: cleanup audit plus strict safety decision.

## Safety Rule Applied

A method body is `DELETE` only if all are true:

- The body still exists as a `CHARACTER::` or `CItem::` definition.
- The body is pure delegation to an ECS API or an obsolete read mirror.
- There are no direct callers outside bridge/subsystem code.
- There are no active calls from other remaining legacy method bodies.
- The body has no service, packet, DB, sectree, event or write/sync side effects.

If any of those checks failed, the method was kept.

## Decision

No method body was deleted in this pass.

Reason:

- The already-obsolete bodies for many migrated accessors are already absent.
- The bodies that still exist are either active from other legacy method bodies, active direct callers, or write/service bridges.
- Deleting any of them now would either fail the build or silently cut a subsystem bridge that Phase 15E-final.1+ is supposed to own.

Recommended next cleanup:

1. Run a small caller-side rewire phase for `GetGMLevel`, `GetRaceNum`, `GetPoint`, `IsImmune` and possibly mount state calls.
2. Re-run this categorization.
3. Delete bodies only after their system refs reach zero or after the owning subsystem extraction replaces the internal calls.
