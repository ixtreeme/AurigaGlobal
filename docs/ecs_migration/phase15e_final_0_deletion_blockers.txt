Date: 2026-05-02
Scope: blocker inventory for actual `CHARACTER` and `CItem` class deletion.

## Current Blocking Surface

After Phase 15E-66.2 / 15E-66.3 planning, the broad ECS `LPCHARACTER` / `CHARACTER*` surface is 117 matches. The remaining surface is no longer safe M1/M2 signature cleanup. It is mostly M3: legacy method bodies, packet encoding, event callbacks, service bridges and subsystem behavior.

Additional method-body inventory:

- `CHARACTER::` definitions remaining: 751
- `CItem::` definitions remaining: 138

## External Constraints

These can block class deletion even when gameplay state has an ECS component:

- Packet binary compatibility: client packets still expect existing payload layout.
- DB/save format compatibility: player/item rows and save timing cannot change accidentally.
- Quest Lua API compatibility: script-visible behavior must stay stable.
- Manager singletons: `CHARACTER_MANAGER`, `ITEM_MANAGER`, `DSManager`, shop, exchange and dungeon managers still own service lifecycle.
- Event scheduler compatibility: existing event payloads often carry legacy object pointers.
- Sectree/network descriptor ownership: these are accepted service boundaries, not pure ECS state.

## Critical Path

The deletion critical path is:

1. NetworkSync extraction.
2. Combat flow extraction.
3. Inventory/CItem service extraction.
4. ItemSystem_LegacyBridge split/removal.
5. Movement/AI callback extraction.
6. Final header pruning and compile deletion pass.

The first four are sequential risk gates because they touch packet compatibility, damage/loot correctness, item persistence and CItem lifecycle.
