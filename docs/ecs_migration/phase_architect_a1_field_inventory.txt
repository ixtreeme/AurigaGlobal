Phase 15E-final.LPENTITY.4-architect.A.1 - Field-level inventory
=================================================================

Scope: catalog every direct read and write of the 10 legacy CHARACTER /
CEntity fields enumerated in the desync audit (section 7.2). Output is
the input for Phase A.2 (component ownership matrix) and Phases B and
C (read / write migration).

Methodology: ripgrep against SRC/Server/GameServer/ for each field
name. Reads are sites that consume the value. Writes are sites that
assign a value. Assignment chains (a = b = c) are counted under each
target. Comments and audit-only references in EntityNetworkDispatchAudit
are excluded; that TU deletes in Phase G.

Build base: HEAD = 15afbfb (audit doc commit), branch ECS_+_BGFX.

Conventions:
  R     direct read of the field
  W     direct write to the field
  RW    read-modify-write (e.g. SET_BIT, ++)
  *     site already mirrored to ECS via Sync*Write helpers introduced
        in 4-fixup.1
  !     site of historical drift discussed in earlier audit

======================================================================
PHASE A.2 PRE-WORK NOTES
======================================================================

A.2 must answer for each field:
  1. Does an ECS twin already exist?  (yes for 8/10, no for m_posStart
     and m_iViewAge)
  2. Is the legacy field's purpose semantically equivalent to the ECS
     twin? (yes for 8, m_iViewAge becomes obsolete in event-driven,
     m_posStart can fold into a function-local arg)
  3. Which subsystem becomes the OWNER (component lifecycle holder)?
     - Position / PositionZ — owned by SpatialService (already)
     - MovementDestination — owned by MovementSystem
     - MovementState — owned by MovementSystem
     - StatusFlags — multiple writers; owner clarified per field
       (StatusFlags itself stays composed, no single owner)
     - ViewMap / ViewerMap — owned by VisibilitySystem (NEW in Phase D)
     - SectorPlacement — owned by SpatialService (already)
