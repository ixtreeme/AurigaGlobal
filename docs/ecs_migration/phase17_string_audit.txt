- Skip: packet decode boundaries and DB row fields until an adapter layer exists.

8. Recommended Phase Plan
-------------------------
Phase 17a - Tier 1 safe function parameters
- Target: selected `const std::string&` parameters.
- Estimated initial scope: 80-120 of 265, not all 265.
- Risk: low if limited to parser/config/internal helper functions.
- Suggested first batch:
  - group_text_parse_tree.cpp/.h
  - text_file_loader.cpp/.h
  - small pure helper functions in config/cuberenewal/cmd_gm
- Defer:
  - questmanager/questpc until Lua lifetime review.
  - char.h public API until CHARACTER migration impact is assessed.
  - DB APIs that pass to C SQL/file boundaries.

Phase 17b - Tier 2 local string allocation and substr cleanup
- Target: 30 substr calls plus selected local read-only std::string temporaries.
- Estimated scope: 50-100 edits.
- Risk: medium due lifetime issues.
- Start with ProtoReader/CsvReader/config parser paths.

Phase 17c - Tier 4 primitive C string operation cleanup
- Target: strcpy/strncpy/strcat first, then selected strcmp/strncmp.
- Estimated scope: 55 write-family calls first, then selected compare calls.
- Risk: low to medium.
- Must preserve fixed-size packet/DB buffer semantics.

Phase 17d - Limited runtime char[] member cleanup
- Target: only runtime storage, not packet/DB structs.
- Estimated scope: very small in Phase 17.
- Risk: high.
- Defer most char[] fields to Phase 19 capnproto/protocol work.

9. Risk Assessment
------------------
Low risk:
- Pure read-only internal helper parameters currently taking `const std::string&`.
- Parser utilities where caller lifetime is local and obvious.
- Replacing simple strcmp with string_view equality inside already owned strings.

Medium risk:
- Local std::string to string_view conversions.
- substr conversions.
- Quest engine helpers due Lua string lifetime and quest context lifetime.
- DB row parsing helpers due null-termination and SQL escaping assumptions.

High risk:
- Packet structs and common/Headers fields.
- tables.h DB serialization fields.
- input_* packet handlers.
- char[] members with protocol-visible layout.
- Any function passing data to fopen, socket APIs, Lua C API, MySQL/MariaDB, or legacy varargs.

Final recommendation:
- Phase 17 should only target Tier 1 safe function parameters.
- Do not attempt tree-wide `const char* -> string_view` conversion.
- Define a convention first:
  - Accept `std::string_view` for internal read-only text.
  - Convert to `std::string` only at C API boundaries that require null termination.
  - Never store string_view in long-lived objects unless the owner lifetime is explicit.
  - Never put string_view in packet/DB structs.
