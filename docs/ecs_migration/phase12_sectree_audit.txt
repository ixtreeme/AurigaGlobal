Additional findings
-------------------
  - `SECTREE` itself is relatively small; most complexity sits in `SECTREE_MANAGER` / `SECTREE_MAP`.
  - The runtime tree is generic over `LPENTITY`, so any ECS replacement must account for CHARACTER, ITEM, and OBJECT coexistence.
  - Neighbor caching (`m_neighbor_list`) is a core behavioral assumption for around-view queries.
  - Map bootstrap, map metadata, and runtime spatial queries are mixed inside the manager layer and should likely be separated in future work.

Migration outlook
-----------------
  - Runtime spatial query migration difficulty: HARD
  - Map/bootstrap migration difficulty: MEDIUM
  - Suggested future decomposition:
    - Phase 12a: read-only wrappers around `Get`, `Find`, and around-view traversal
    - Phase 12b: ECS bridge for entity placement / visibility while keeping legacy sectree authoritative
    - Phase 12c: attribute and movable-position bridge
    - Phase 12d: private-map / map-loading isolation
