## 4. Phase 15E-61 Sub-Batch Proposal

### Phase 15E-61.1 - Simple Read Accessors

Targets:
- GetExchange
- GetInventoryItem
- GetWear
- MountVnum

Approach:
- Add entity-first read APIs in InventorySystem, ItemSystem or MountSystem.
- Keep ownership/service semantics unchanged.
- Migrate caller side in small file batches.

Risk:
- Medium. Inventory/equipment paths are gameplay-critical but mostly read-only.

Estimated caller-side calls:
- Around 150 from the targeted list, before false-positive filtering.

### Phase 15E-61.2 - Simple Predicates

Targets:
- IsObserverMode
- IsDead
- IsStun
- CanUseSkill
- Possibly CanWarp after logic review

Approach:
- Use StatusFlags/tags or add small state components.
- Verify all write paths sync into ECS before removing legacy reads.

Risk:
- Medium-high. Dead/stun/warp predicates affect combat, login, map transfer and command handling.

Estimated caller-side calls:
- Around 100 from the targeted list.

### Phase 15E-61.3 - Movement / Warp Writes

Targets:
- WarpSet
- ExitToSavedLocation
- Goto
- Show
- Stop
- Move
- OnMove

Approach:
- Domain-specific MovementSystem/NetworkSyncSystem APIs.
- Preserve position sync, sectree registration and packet visibility semantics.

Risk:
- High. This touches the same class of issues as the mounted-position/metin damage regression.

Estimated caller-side calls:
- Around 210 from the targeted list.

### Phase 15E-61.4 - Quest / State Machine / Click Behavior

Targets:
- SetQuestNPCID
- StartStateMachine
- SetState
- OnClick
- Quest `SetFlag/GetFlag` family after separate quest flag audit

Risk:
- High. Quest state and click routing are behavior systems.

Recommendation:
- Audit-only or dedicated QuestSystem phase, not mixed with movement or inventory.

### Phase 15E-61.5 - Service / Persistence / Network

Targets:
- Disconnect
- Save
- Any remaining Packet/BufferedPacket/DBPacket/DESC operations

Risk:
- High. Requires service abstraction and process boundary awareness.

Recommendation:
- Defer until GameServer service API boundaries are explicitly designed.

## 6. Recommended Next Action

Recommended next phase: Phase 15E-61.1.

Start with read-only accessors:
- GetExchange
- GetInventoryItem
- GetWear
- MountVnum

Reason:
- They have clearer ownership than warp/show/network writes.
- They reduce caller-side CHARACTER dependence without immediately touching position, sectree or network visibility.

Explicit deferrals:
- Do not bulk-migrate `Show`, `WarpSet`, `OnMove`, `ExitToSavedLocation` in the same batch.
- Do not treat top raw method names such as `SetFlag/GetFlag/Packet/Get` as CHARACTER methods without class-context review.
- Do not migrate Category D/E methods in 15E-61.1.
