Step 2 - Shared Entity-First Helper Surface

Changes made to quest context helpers:
- Added to `CQuestManager`:
  - `entt::entity GetCurrentPCEntity() const;`
  - `entt::entity GetCurrentNPCEntity() const;`
- Kept compatibility wrappers:
  - `GetPCEntity(lua_State* L)` now forwards to `GetCurrentPCEntity()`
  - `GetNPCEntity(lua_State* L)` now forwards to `GetCurrentNPCEntity()`
- Added shared bridge helper in `ecs/CharacterAccessors.hpp`:
  - `ecs::LegacyCharOf(entt::entity e)`

This means quest bindings can now start from entity context without re-implementing `LegacyCharPtr` resolution locally.

Step 4 - Pattern Distribution

Pattern distribution observed in this pass:
- Pattern A (pure ECS direct read): already existed in a subset of questlua bindings before this pass, especially where `GetPCEntity(L)` plus `ECS_TryGet` or `ecs::Get*` accessors had already been introduced.
- Pattern B (entity-first + `ecs::LegacyCharOf(e)` bridge): dominant in this pass.
  - Count: 345 migrated binding starts.
- Pattern C (quest flag / player data / legacy-only state): also common.
  - In these functions the binding now starts from entity context, but the actual operation still goes through the bridged `CHARACTER*` because quest flags, inventory, guild, desc, safebox, and similar state remain legacy-authoritative.

Practical summary:
- This was primarily a mass Pattern-B / Pattern-C cleanup pass.
- It intentionally did not try to invent new ECS component authority for quest/player/safebox/guild state.
