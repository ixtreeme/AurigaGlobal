# Phase 15E-65.2 Item Write Sync

Generated: Phase 15E-65.2

## 1. Scope

Goal: add ECS sync coverage for identified item write paths without removing any read fallback.

Important rule:

- Read fallback remains in place until Phase 15E-65.4.
- This phase only improves write-side ECS freshness.

## 2. Existing Sync Coverage Found

`ItemSystem_LegacyBridge.cpp` already syncs most central legacy item mutations:

- `CItem::SetCount` calls `SyncItemCountComponent`.
- `CItem::SetSocket` calls `SyncItemSocketsComponent`.
- `CItem::SetSockets` calls `SyncItemSocketsComponent`.
- `CItem::SetAttribute` calls `SyncItemAttributesComponent`.
- Item flag mutations call `SyncItemFlagsComponent`.
- `ItemSystem::SyncItemStateFromLegacy` already syncs identity, count, prototype metadata, flags, location, owner, sockets and attributes.

Conclusion:

- The item_manager post-create `SetSocket` / `SetCount` clusters are already covered by central CItem write hooks when the item has an ECS entity.
- Pre-hydration writes during `ITEM_MANAGER::CreateItem` are captured by the final `EntityFactory::CreateItemEntity` hydration.

## 3. Fix Applied

Missing sync found:

- `CItem::SetAttributes(const TPlayerItemAttribute*)` copied the full attribute array and saved the item, but did not mirror to ECS.
- `CItem::CopyAttributeTo` uses `SetAttributes`, so accessory/refine attribute-copy paths could leave `ItemAttributes` stale.

Fix:

- Added `SyncItemAttributesComponent(this)` after the `memcpy` in `CItem::SetAttributes`.

Commit:

- `Phase 15E-65.2: Sync bulk item attributes from legacy`

## 4. Remaining Direct Legacy Write Audit

- `item_manager.cpp:713 SetCell` and `new_offlineshop.cpp:481 SetWindow` are Phase 15E-65.4 candidates because location setters are inline legacy writes and need dedicated ECS location sync review.
