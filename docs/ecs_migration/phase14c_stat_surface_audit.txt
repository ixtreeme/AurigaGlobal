Phase 14c - NetworkSyncSystem full stat surface audit
Date: 2026-04-18
Workspace: E:\AurigaGlobal\LiveWork\AurigaGlobal

Scope
- Audit only. No gameplay code changes.
- Compare legacy stat packet authority against active ECS NetworkSyncSystem output.
- Identify exact gaps that caused the previous zero-stat UI regression risk.

Summary
- Legacy stat UI authority is still CHARACTER::MainCharacterPacket() + CHARACTER::PointsPacket().
- Active ECS NetworkSyncSystem_Update() only sends:
  - TPacketGCMove
  - partial TPacketGCPoints with HP / MaxHP / SP / MaxSP / optional Stamina
- ECS currently does not send Level, EXP, Next EXP, Gold, base attributes, status points, skill points, attack/defense grades, or the rest of the POINT_* surface.
- Login seeding already populates Health, Mana, LevelComponent, Experience, and GoldAmount.
- Login seeding does not currently populate Stamina or full CharacterPoints from input_db.cpp.
- Safe near-term strategy: keep legacy stat packets authoritative, keep ECS NetworkSyncSystem sync-only until full POINT_* coverage exists.

2. Legacy PointsPacket contents
========================================================================

Authoritative implementation
- File: SRC/Server/GameServer/ecs/systems/NetworkSyncSystem.cpp:727-755

Explicitly written fields before the generic POINT_* loop
- POINT_LEVEL
- POINT_EXP
- POINT_NEXT_EXP
- POINT_HP
- POINT_MAX_HP
- POINT_SP
- POINT_MAX_SP
- POINT_GOLD
- POINT_STAMINA
- POINT_MAX_STAMINA
- POINT_INVEN (conditional: __ENABLE_EXTEND_INVEN_SYSTEM__)

Generic stat surface written via loop
- for (int i = POINT_ST; i < POINT_MAX_NUM; ++i)
  - pack.points[i] = GetPoint(i)

Implication
- The legacy path sends far more than the eight base vitals.
- It covers the full POINT_* runtime surface starting at POINT_ST.
- This includes, at minimum:
  - base attributes: POINT_ST, POINT_HT, POINT_DX, POINT_IQ
  - combat grades: POINT_ATT_GRADE, POINT_DEF_GRADE, POINT_MAGIC_ATT_GRADE, POINT_MAGIC_DEF_GRADE
  - speeds: POINT_ATT_SPEED, POINT_MOV_SPEED, POINT_CASTING_SPEED
  - unspent points: POINT_STAT, POINT_SKILL, POINT_SUB_SKILL
  - recovery / regen values
  - crit / pen / poison / stun / slow / curse
  - class / race / element attack bonuses
  - resistances
  - bonus grades and many later POINT_* extensions

Conditional tail fields
- POINT_GAYA (conditional: ENABLE_GAYA_SYSTEM)

Conclusion
- Legacy PointsPacket is a full stat snapshot packet.
- Any ECS replacement that only sends HP/SP will necessarily regress the local stat UI.

9. Recommended sync strategy
========================================================================

Current safe authority model
- Keep legacy MainCharacterPacket() authoritative.
- Keep legacy PointsPacket() authoritative.
- Keep active ECS NetworkSyncSystem_Update() sync-only until the full stat surface is covered.

Why
- Previous zero-stat regression came from enabling NetworkSyncSystem_Update() while ECS only had partial HP/SP data on the send path.
- This audit confirms that the active ECS sender still lacks most of the legacy stat UI surface.

Minimum requirements before any authority switch
1. Seed and maintain Stamina on login and runtime updates.
2. Seed and maintain full CharacterPoints / POINT_* state.
3. Map CombatStats and any derived grades/speeds into the outgoing packet surface.
4. Expand active ECS TPacketGCPoints construction to fill every field that legacy PointsPacket currently fills.
5. Decide whether PointChange remains legacy or gets a matching ECS incremental path.
6. Only after 1-5 are complete, evaluate replacing legacy caller sites.

Recommended migration mode for Phase 14x
- NetworkSyncSystem should remain sync-only observer.
- Legacy packet call sites should not be disabled yet.
- Any future ECS send enable should be gated behind field-complete parity with PointsPacket.

========================================================================
10. Bottom line
========================================================================

Findings
- The active ECS NetworkSyncSystem does send stat UI data, but only a narrow vital subset.
- The legacy PointsPacket sends a much broader POINT_* surface.
- ECS already stores some of the missing data, but does not send it.
- Other missing data is not even seeded yet at login.

Risk classification
- Enabling NetworkSyncSystem_Update as an authoritative stat sender today is HIGH RISK.
- It will regress local-player stat UI again unless the full legacy packet surface is mirrored.

Recommended next step
- Do not enable NetworkSyncSystem_Update yet.
- Next technical slice should be:
  - full POINT_* seed audit
  - CharacterPoints runtime sync
  - ECS PointsPacket parity implementation
  - only then a guarded WinTest re-enable attempt
