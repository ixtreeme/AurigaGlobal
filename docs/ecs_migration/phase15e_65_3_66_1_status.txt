# Phase 15E-65.3 + 15E-66.1 Status

Generated: Phase 15E-65.3 + 15E-66.1

## 1. ItemProtoRef Component

Added:

- `SRC/Server/GameServer/ecs/components/item_proto_components.hpp`
- `ecs::ItemProtoRef`

Purpose:

- Store proto-derived item data on the item entity.
- Allow item read APIs to avoid `LegacyItemOf` / LPITEM resolution for proto fields.

## 2. Factory Population

`EntityFactory::CreateItemEntity` now hydrates `ItemProtoRef` through the shared `SyncItemEntity` path.

Captured fields:

- Base vnum, type, subtype
- Weapon/min-max, defense, magic min/max
- Name, size
- Level limit, wear flags, anti flags, immune flags
- Refined vnum, refine level
- Limit timer based on wear index
- Transitional `const TItemTable* proto`

## 3. Proto-Derived Reads Migrated

The following `ItemSystem` reads now use `ItemProtoRef` and no longer resolve LPITEM:

- `GetItemValue`
- `GetItemName`
- `GetItemSize`
- `GetItemRefineVnum`
- `GetItemRefineLevel`
- `GetItemLevelLimit`
- `GetItemLimitTimerBasedOnWearIndex`
- `GetItemWearFlags`
- `GetItemWearFlag`
- `GetItemAntiFlags`
- `GetItemAntiFlag`
- `GetItemImmuneFlags`
- `GetItemProto`

Note:

- `GetItemValue` and `GetItemProto` still use the transitional proto pointer stored in `ItemProtoRef`.
- They no longer call `LegacyItemOf` or `ResolveLegacyItemForLegacySideEffect`.

## 4. Invariant Coverage

`ItemInvariants` minimum item component set now includes:

- `ItemProtoRef`

Runtime missing proto hydration will show as:

```text
[ITEM_INVARIANT] entity=<id> ctx=<context> missing component ItemProtoRef
```
