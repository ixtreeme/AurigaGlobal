35cbd25 - 4-fixup.0: Movement state drift audit
  New: docs/ecs_migration/phase15e_final_lpentity_4_fixup_audit.txt
  Lists 12 confirmed write-path drift sources between legacy CHARACTER
  fields and parallel ECS components consumed by native dispatch:
    - 5 movement-field sites (m_posDest, m_dwMoveStartTime,
      m_dwMoveDuration, m_bNowWalking)
    - 4 m_bAddChrState writes without StatusFlags companion
    - 2 reverse-direction StatusFlags writes without m_bAddChrState
    - 1 KASMIR shop sign field hard-coded in native dispatch
  Documents WinTest matrix and out-of-scope items.
  No source code change.

eb88cd9 - 4-fixup.1: Sync*Write API skeleton
  Modified: ecs/systems/MovementSystem.hpp
  Modified: ecs/systems/MovementSystem.cpp

  Added four namespace-level helpers in ecs::MovementSystem:
    SyncDestinationWrite(e, x, y)
      emplace_or_replace<MovementDestination>
    SyncDestinationClear(e)
      remove<MovementDestination> + zero MovementState timing
    SyncTimingWrite(e, startTime, duration)
      patch MovementState moveStartTime and moveDuration
    SyncWalkingWrite(e, isNowWalking)
      patch MovementState isNowWalking

  All helpers are no-op safe on null/invalid entities.
  No callers in this commit.

  remains in place. Item, Building, OfflineShop dispatch is native

Pending: WinTest checkpoint

The plan gates 4-fixup.5 (native character dispatch re-enable) on
zero-warning WinTest of the matrix in the 4-fixup.0 audit doc.

Required scenarios:
  1. Two clients in mutual view, walk / run / mount toggle
  2. Mid-move login of a third client
  3. Stun / dash mid-walk
  4. Map warp + viewer crossing boundary
  5. Observer mode toggle on / off
  6. Character death and respawn
  7. Drift-injection negative test: temporary commit that bypasses one
     Sync*Write helper, verify [MOVEMENT_DRIFT] fires for the affected
     entity, then revert. This proves the detector is not placebo.
